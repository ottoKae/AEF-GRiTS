# AEF-GRiTS 本地运行、网页操作：GUI 与发布执行计划

日期：2026-10-30。状态：已实施首版本地 GUI、认证入口、打包启动与附加 GeoTIFF 交付；完整公开源下载、真实账户验收及三平台实机认证仍未完成。

实施结果与测试证据保存在开发者本地的 `webapp/acceptance/local_gui_20261030/`，属于未随仓库发布的历史验收材料。下文的现状表保留实施前检查依据；实际用法以 [GUI 使用说明](web-portal.zh-CN.md) 为准。

本计划替代上一版“公开服务器为用户加工并托管结果”的主路线。公开官网负责介绍、安装指引和传播；下载 GUI 与 Python 引擎在用户电脑运行。已有共享 Web 模式保留兼容，但本次不扩展、不部署。

## 1. 产品目标与边界

用户只需首次安装工具包，此后运行一个命令，浏览器打开本地 GUI。所有选择、认证、预检、下载和结果查看都在网页完成；用户不必编写 Python，不必安装桌面 GUI 框架。

```text
公开官网：介绍、作者、安装说明、教程、版本、源码
                   ↓ 用户安装并主动启动
本机浏览器：http://127.0.0.1:5555/portal
                   ↓ 同机请求
本机 Python：认证 → 查询 → 有界下载 → 验证 → 本机目录
                   ↕
              GEE / 公开 AEF 数据源
```

公开官网不保存用户凭据、不接收样本、不搬运影像、不承担加工队列。它不远程执行用户 Python，也不持续探测用户本机端口。

### ponytail 约束

- 复用现有 Flask、Leaflet、HTML/CSS/JS、认证 CLI、任务调度、格网/点位解析、Zarr/Parquet 写出和验证器。
- 不引入 React/Electron、桌面窗口框架、浏览器扩展、微服务、数据库队列或另一套数据格式。
- 不把现有 `/` 和 `/portal` 复制成两套下载后端；四步逻辑共享，默认启动 `/portal`，保留原入口兼容。
- 不做常驻服务、自启动、自定义 URL 协议、静默升级或完整离线环境安装器。首版前台 Python 进程足够。
- 不为公网交付打包整个 Zarr，不实现浏览器目录流式写入，也不设置本地结果72小时自动删除。
- 保留入口校验、断点、磁盘/内存预算、凭据脱敏及本地访问边界，不因“本地运行”移除这些约束。
- 所有未提交改动与已下载数据保留；不自动迁移、删除或推送。本计划不授权软件发布、真实账号登录或大规模下载。

## 3. 首次安装与日常启动

### 3.1 用户最终体验

1. 官网选择Windows/macOS/Linux，按说明建立独立Python环境。
2. 安装带`download,web`依赖的发行包。
3. 运行`aef-grits-web`，浏览器自动打开本地工作台。
4. 完成P0—P3，下载到本机输出目录。

`aef-grits-web`已在本轮实现，并通过仓库外 wheel 安装检查；尚未发布本次发行版。当前可从本地源码安装，或使用本地构建并验收的 wheel，不能把旧的线上版本视为包含本轮功能。

首版优先认证现有CI覆盖的Python 3.11/3.12。项目声明的其他Python版本是否可用由测试决定，不把声明范围当作全部平台认证结果。

### 3.2 启动器最小职责

- 参数仅提供实际必要的`--port`、`--no-browser`、`--output-root`、`--state-dir`，沿用已有环境变量；优先级为显式参数 > 已有环境配置 > 默认值。
- 固定loopback监听，不新增公网`--host`入口；`--no-browser`供无图形环境/诊断使用。
- 先解析参数、验证目录及依赖，再加载应用。成功监听后才打开浏览器，避免打开一个尚不存在的页面。
- 使用标准库`webbrowser`；打开失败则打印URL，不能因此关闭可用服务。
- 默认端口占用时明确报错并提示换`--port`，不自动杀进程、扫描大量端口或启动多套隐蔽后台服务。
- 使用当前`sys.executable`启动工作子进程，缺少依赖即说明当前环境与修复方式。
- 关闭浏览器标签不终止任务；退出Python、关闭运行终端、系统休眠/断网可能中断。重启后展示检查点，由用户主动续传，不自动开始计费/耗流量任务。
- 保留已有退出和进程树管理；不为这个发行改造替换整个调度框架或强制引入生产WSGI服务。

### 3.3 安装包内容与运行目录分离

最小选择是把现有`webapp`包加入setuptools发现范围，并仅列入必需HTML、CSS、JS、图标及已有第三方静态资源；不为命名整齐先迁移全部模块。

wheel中必须包含：Web Python模块、GUI资源、既有CLI、权威MGRS索引。不得包含：`runs/`、`output/`、PID、日志、凭据、测试下载、acceptance截图和个人配置。以实际wheel内容检查为准，不依赖仓库`.gitignore`代替打包规则。

运行目录建议：

| 内容 | 默认位置策略 |
|---|---|
| 状态、计划、日志、PID | 当前用户独立状态目录；Windows优先LOCALAPPDATA，macOS用户Library/Application Support，Linux优先XDG_STATE_HOME或其标准回退 |
| 数据输出 | 用户目录下`Downloads/AEF-GRiTS`作为可改默认值；界面明确显示最终绝对路径 |
| EE/ADC凭据 | 继续使用认证库既有位置，不复制到GUI目录或数据目录 |
| 公开源索引缓存 | 归入本工具用户状态/缓存范围，记录来源版本；不是全量影像镜像 |

使用现有工具或少量标准库路径判断，不单为这几条路径增加依赖。对旧源码运行已经产生的数据不自动移动：升级说明提供显式`--state-dir`和`--output-root`复用方法。

研究数据保存到用户自选的 AEF 数据根目录，沿用该目录的组织规范；默认下载目录不替代用户已有的数据管理规则。开始真实下载前先查已有 embedding catalog，避免重复下载。

## 4. GUI：P0—P3 四步不变，职责改为本机执行

```text
顶部：AEF-GRiTS | 嵌入式特征数据下载工具 | 本机运行 | 帮助/作者
┌──────────────────────┬─────────────────────────────────┐
│ P0 数据源与连接      │ 地图：点位、AOI、目标格网        │
│ P1 点位或格网        │ 图例、覆盖与CRS说明              │
│ P2 年份与查询        │ 点击查看格网/点位信息            │
│ P3 本机目录与下载    ├─────────────────────────────────┤
│ 配置进度与缺失项    │ 查询结果 / 本机下载任务          │
│ 主操作按钮          │ 最新靠左，横向滚动，可展开详情   │
└──────────────────────┴─────────────────────────────────┘
```

沿用现有视觉风格、大字号和L形任务栏。只突出当前步骤，说明文字默认简短，技术细节折叠；字段有可读标签、键盘可操作，错误不只靠颜色提示。配置进度每步25%，与真实下载进度分开。

### P0：数据源与连接

两个选项：`公开AEF源（无需GEE登录）`和`Google Earth Engine（本机授权）`。公开源的具体提供方只有通过验证后才启用，不自动切换来源。

**公开源：**本机Python验证索引和代表性对象访问。此路线不需要网站账户、不需要GEE Project；所有加工也在本机，不再引入官网登录来“领取计算配额”。浏览器不直接请求影像，COG Range读取由本机Python完成，因此不以源端浏览器CORS作为主路线门槛。

**GEE：**明确文案“授权本机下载工具访问 Earth Engine；凭据保存在本机，不上传官网”。具体流程：

1. 检测既有凭据，只显示来源与是否存在，不能把“找到凭据”显示成“已成功连接”。
2. 无凭据时用户主动点击“连接Earth Engine”；本机服务启动已有`aef-grits-auth login --source earthengine --auth-mode localhost`流程，浏览器进入Google授权页面。
3. 登录进程独立于下载worker，页面显示等待/完成/失败；取消时不遗留认证进程。只允许一个进行中的本地认证，防止重复点击争用回调端口。
4. 用户填写自己的Project ID，或复用私有本地设置。调用既有verify与一个轻量AEF查询验证该凭据/Project组合；分别显示权限、项目配置、配额和网络错误。
5. 验证通过才点亮P0。之后下载和重试不得再次自动触发登录；失效进入`auth_required`，用户主动重新认证后续传。

本地GUI已有“本地用户身份就绪”不等于Google认证成功。界面将`凭据发现`、`Project验证`、`AEF可访问`分开表达。[官方认证与初始化说明](https://developers.google.com/earth-engine/guides/auth)

保留现有凭据优先级与显式来源规则，不因EE失效自动借用另一账号ADC。若使用显式环境凭据导致新登录不会被采用，清晰提示当前来源，不静默修改用户环境。

为避免共享本地凭据文件在运行任务中途被替换，切换来源/Project影响新计划；有运行或排队GEE任务时，先完成/取消这些任务再执行强制重新认证。此处先用简单限制，不建设多用户凭据快照系统。清理EE/ADC凭据可能影响同机其他工具，必须明确告知，普通退出GUI不删除它们。

官网不申请用户Google授权，不保管refresh token，不需要一套公开网站OAuth client来支撑这条本地路线。既有共享部署认证保持原样，单独文档说明。

### P1：位置——点位与格网

| 方式 | 文件输入 | 地图输入 | 检查与反馈 |
|---|---|---|---|
| 点位 | WGS84 CSV：sample_id/lon/lat；带CRS的Point Shapefile | 点击增删多个点 | 点数、重复、非法坐标、输入CRS、可见定位 |
| 格网 | Polygon Shapefile等现有支持的AOI格式 | 绘制AOI，再勾选相交MGRS/0.1°格网 | AOI范围、目标格网ID/数量、目标UTM |

保留既有解析能力，不为新GUI另造格式转换器。Shapefile检查完整组件与CRS；Polygon不静默转点；输入来源切换后仅当前文件/绘制结果生效。

地图展示WGS84，输出使用目标UTM；0.1°格网是AEF存储单元，不是Tessera产品。公开源原生COG足迹与目标格网分别绘制/标注，不能拿“相交COG”冒充MGRS Zarr。

### P2：年份与查询

- 展示当前来源实际支持的年度，可多选，不显示月/日粒度。
- 查询由本机Python完成，返回按年份的点位/格网覆盖、来源、CRS、格式与估算量。
- 只做库存查询和必要预检；不能在用户确认前启动全量提取。区分覆盖存在与像元有效性，后者未读数据时标注待验证。
- 查询结果保留现有plan确认机制；来源、位置、年份、采样格式、Project或输出目录改变，需要重新确认相应计划。
- 未知压缩比或源字节数显示未知/估算，不给伪精确的下载时间。

### P3：本机目录与开始下载

页面显示“本机输出根目录 + 任务子目录 = 最终保存位置”，复用现有根目录内浏览/新建子目录控件，允许输入子目录名。无需浏览器File System Access API，也不要求原生文件对话框或tkinter。

输出根目录通过启动参数设定，首次默认值可用。GUI设置面板提供明确修改说明与可复制启动命令。首版不在任务运行时切换全局输出根目录；选择另一磁盘先结束当前任务再按指定根目录重启，避免改写共享状态。若后续确需每任务跨盘，另行设计，不默默放开全盘文件管理接口。

最终检查可写性、磁盘容量、资源预算、输入与目标路径，确认plan后本机worker开始下载。数据直接保存为既有Zarr/Parquet及catalog，不再为“交付到用户电脑”创建大型ZIP副本。

结果区提供最终路径、复制路径、报告及完成验证。首版不新增全盘文件浏览、文件删除API或任意程序执行接口；也不为了“打开文件夹”增加跨平台桌面依赖。

### 任务显示与可恢复性

- 状态：排队 → 查询/读取 → 写入 → 验证 → 完成；错误、取消、中断、需认证明确区分。
- 进度以块/分片为依据；速率和ETA有测量基础才显示，无分母时用阶段状态。
- 任务卡完整展示点数/格网ID、年份、来源、最终路径、已完成量、错误原因，长文本可展开。
- 原始COG整文件下载也由本机Python执行并报告字节进度，不将“浏览器打开链接”当作下载完成。
- 关闭标签页后重新访问可见原任务；进程重启不自动重复已完成数据。已验证完成才标记done。
- 结果长期保留，由用户管理；不从云端方案继承TTL自动删除。

## 5. 下载链路与科学一致性

### GEE路线

保留computeFeatures→点位Parquet、computePixels→格网Zarr及既有重试、资源预算和检查点。只修正必要的打包/路径/调用方式，不借GUI改造重写成熟下载逻辑。

### 公开COG路线

以官方原生UTM COG及其索引为首选候选，先验证匿名可读、年份、CRS、NoData、方向和Range读取，再启用按钮。Source Cooperative原生副本只在自身验证后作为显式备选，4326 mosaic不作为首期替代。

最小实现为一个明确的来源读取模块，复用既有点位/格网组织、写出、资源控制、验证和结果索引，不建立通用provider插件框架。

- 点位：按源对象/窗口分组读取，避免每点重复拉取同一块；先复用现有分组模式，量测后再优化。
- 格网：有限窗口流式读取，不能将完整MGRS或年度数据全量载入内存；必要的重投影也须分块。
- 64维int8原始编码先屏蔽NoData，再按官方规则解码；源存储编码不等于模型float特征。基础像元提取不能误用overview。[官方GCS数据说明](https://developers.google.com/earth-engine/guides/aef_on_gcs_readme)
- 同为UTM 10m仍须核查transform、原点、尺寸、像元中心和掩膜。需要重采样时记录方法，不能宣称重新对齐是严格无损。
- 保留当前Zarr维度、calendar/catalog、float32及压缩约定；读者不应因新GUI失去兼容性。
- provenance记录来源、对象标识/版本、年份、解码/采样、输出格网和软件版本；没有Git工作树时使用安装包版本，不读取无关当前目录的Git记录。

先用少量跨年份/UTM样本对照GEE，报告数值/余弦差异、坐标及缺失，不预设两来源bit-exact。匿名路径验证失败时禁用该路径并解释，不伪装成GEE下载或使用管理员账号。

## 6. 本地服务边界与性能

保留127.0.0.1监听、Host与跨Origin写请求检查。官网只是链接和说明，不能获得本地下载API的跨域控制权限；不配置允许任意网站访问localhost的CORS。

具体风险是其他网页诱导浏览器向本地接口发起登录、写目录或下载请求。复用现有校验，并为实际新增入口补同源/会话验证及测试；认证启动不得使用会产生副作用的公开GET。不要因本地服务无密码就把路径写入或进程启动开放给任意Origin。

保持现有内存、磁盘、并发及Linux NTFS保护，不增加云端用户日配额。前台页面显示本机资源预检结果，不假设内存越多就应无限增大并发。

单个源年度大任务之前先跑点位/小格网，记录峰值RSS、请求数量、源字节、写出字节、速率、错误与恢复开销。性能目标是资源有界、不中断结果一致；实际吞吐用测试报告，不先给保证值。

## 7. 公开官网：静态入口，而非远程控制台

优先一页静态网站加已有文档，不引入构建框架。拟放在`website/`，独立于Python运行资源；实际发布平台/域名需另行确认，编写文件不等于授权部署。

页面内容按顺序：

1. 工具功能、AEF介绍、作者与源码；明确“免费开源，本机运行”。
2. 三平台安装步骤：环境、固定版本包、启动命令；展示真实已验收组合。
3. “启动后打开本地GUI”链接与URL；用户尚未启动时给出说明，不谎称网站能直接启动Python。
4. P0—P3截图和简短教程；截图来自真实GUI验收并隐去个人Project、凭据与私有路径。
5. 数据存在哪里、如何读取Zarr/Parquet、停止与恢复任务。
6. 常见问题：Google访问失败、Project权限、端口占用、磁盘不足、关闭终端后的行为。
7. 软件版本/引用方式、数据提供方许可与署名、隐私说明、问题反馈。

不设置Google登录入口、文件上传、用户任务面板或支付。首版不增加第三方追踪统计。安装命令可复制；不引导`curl | shell`式不透明远程执行，不要求管理员权限作为默认步骤。

官网可不间断运行，但任务只在用户电脑的Python进程运行时存在执行能力。GCS/GEE连通性依然取决于用户网络，官网无法替代其出口。

## 8. 按顺序执行的工程任务

P0—P3专指用户界面；以下E0—E7是工程顺序，避免混用。

| 顺序 | 任务与关联范围 | 验收出口 |
|---|---|---|
| E0 冻结范围 | 记录工作树、现有端口/运行任务；确认采用本计划，保留旧共享功能 | 不重启正在下载的服务、不触碰已下载数据；测试独立状态目录 |
| E1 可安装与启动 | `pyproject.toml`、Web launcher、静态资源清单、默认目录、子进程模块调用 | 干净环境wheel安装后，从仓库外执行启动命令，页面/静态资源/MGRS/CLI完整 |
| E2 本地认证闭环 | 复用auth_cli；本地GUI认证状态、显式登录、Project验证、失效恢复 | 无凭据不假绿；取消/失败可退出；成功后查询；无自动登录与账号回退 |
| E3 公开源最小读取 | 官方索引/COG读取，接现有写出与校验；按实际支持能力分流 | 不需GEE身份的真实小点位和小窗口提取通过；对照GEE并记录差异 |
| E4 四步GUI整合 | `index.html`、`portal.js/css`、capabilities/plan接口与目录显示 | 两个源均按P0—P3完成小任务，改输入使旧plan失效；数据直接写本机 |
| E5 恢复/资源/回归 | 现有API、认证、打包、浏览器测试；低内存、取消与重启场景 | 原有CLI及本地GUI不回退；有界任务完成，断点恢复一致，凭据不进产物 |
| E6 文档与官网源文件 | 中英文README、Web说明、认证说明、静态官网和实际截图 | 从“官网安装说明”走到“本机产物读取”没有隐含源码依赖；不部署 |
| E7 三平台交付验收 | 扩展现有CI增加wheel路径；真实联网手动验收；汇总限制与版本 | 输出可复核报告及发行候选；用户另行确认后才commit/push/发布/部署 |

E2和E3的逻辑能力先验证，再在E4合并界面，不为每个阶段重写一遍前端。若E3被外部网络阻塞，明确暂不可用，可先交付经过验收的GEE闭环，但不能声称双源任务已完成。

### E1特别检查：不要只测editable安装

构建wheel后在干净venv安装，从非仓库工作目录启动；不依赖`PYTHONPATH`、开发者conda环境、源码静态目录或已有EE凭据。检查wheel排除了运行数据和秘密。启动help不创建任务目录、不访问网络、不打开浏览器。

module调用必须同时更新命令构造测试、相关validator子进程、文档及旧入口，检查所有ROOT/cwd依赖，不仅修正一个主下载调用。源码运行兼容保留，但不是安装用户必需流程。

### E2特别检查：登录与下载分离

首次登录是用户交互测试，不让CI弹出真实Google窗口或读取开发者凭据。自动测试验证真实命令构造与状态变化；真实账号认证由用户操作，报告仅记录结果与匿名化身份来源。

本地GUI登录按钮只调用既有认证CLI；处理其等待、退出、取消和日志脱敏。无Google网页账号可读信息时显示“已验证凭据”，不为展示头像/邮箱额外申请权限。

## 9. 验收矩阵与证据

| 类别 | 最小案例 | 判定 |
|---|---|---|
| 打包 | Windows/Linux/macOS；wheel而非仅editable | 仓库外启动、帮助与静态资源均可用；无site-packages写入 |
| 生命周期 | 端口占用、浏览器打开失败、刷新/关标签、终端退出后重开 | 错误明确；无误杀；任务与恢复行为符合说明 |
| 认证 | 无凭据、已有EE/ADC、无效Project、取消登录、过期凭据 | 不假绿、不自动弹登录、不切换账号；旧plan失效正确 |
| 点位 | WGS84 CSV、投影Point Shapefile、地图多点 | 坐标一致、样本ID和年度正确、64维有效性可核查 |
| 格网 | Polygon上传、地图绘制、单个0.1°格网；MGRS先plan再受控下载 | 真实grid_id、UTM/transform正确、边界无错位 |
| 双源 | 同点/同年份原生COG与GEE | 输出来源清晰，报告数值/掩膜差异，不隐式混合 |
| 存储 | 中文/空格路径、只读/不足空间、重复目标、已有检查点 | 不破坏旧数据；明确失败或恢复；catalog路径可用 |
| 性能与恢复 | 限制内存的小任务；传输中断；进程退出重启 | 峰值内存有界；保存检查点；完成后reader校验通过 |
| 本地边界 | 外部Origin发起写请求；恶意文件名/路径；凭据日志检查 | 拒绝不可信操作，不能越过配置输出边界 |
| UI | 四步缺失项、计划过期、长任务卡、窄屏、键盘 | 无假进度、错误可操作、必要信息不被截断 |
| 官网 | 按页面指引在新环境从头操作 | 不需要Git仓库/个人路径/隐藏安装步骤；版本与命令真实 |

现有三平台CI是基础，不代表已经完成这些认证。尤其macOS真实Google登录、浏览器启动与数据盘权限须记录实际测试，不用Linux模拟结果代替。

小规模真实网络验收先限定点数、年份、窗口和输出预算；批准后再执行。确认网络/数值正确不需要下载整省/全国数据。

测试代码在`tests/`，浏览器证据与实测报告在`webapp/acceptance/<run-id>/`。临时数据使用工作区`.tmp/tests/aef/<run-id>/`并给pytest传独立`--basetemp`，禁用或隔离缓存。不能把真实凭据和正式研究数据作为pytest fixture。

## 10. 交付内容与完成定义

交付应包含：

- 一个包含Web资源的可安装发行候选，正式启动命令与清晰的本机目录策略。
- 一套P0—P3本地GUI，GEE与公开源能力按验收情况明确标记。
- 原格式可读的数据、provenance、运行报告与可恢复检查点；不要求用户下载ZIP后再解包才能用。
- 中英文安装/使用/认证/恢复说明，以及无需后端的官网源文件。
- 三平台测试状态、实际网络与资源测量、未解决问题清单，不用“全通过”掩盖未执行项。

完成标准不是“页面能打开”，而是新用户能按公开说明安装、认证或选择公开源、选空间时间、指定本机存储、完成小规模下载，并用既有reader正确读取产物。

### 2026-10-30 执行补充：可选 GeoTIFF

- 默认保持 Zarr，沿用已有分块、检查点及多年度组织；点位仍使用分片 Parquet。
- 格网可选“Zarr + GeoTIFF”：在完成 Zarr 下载后，按年分窗口导出 64 波段 float32 GeoTIFF，保留 UTM、仿射变换、A00—A63 波段名称与 NaN 掩膜。
- 使用无损 DEFLATE；大文件自动使用 BigTIFF。不进行量化、不降采样、不重新投影。无损指相对下载好的 Zarr，不是恢复源产品本已量化的信息。
- 不删除 Zarr，也不宣称为 TIFF-only；预检为附加 TIFF 增加空间预算。导出失败可重新执行，已有匹配的完整 TIFF 可复用。只在 TIFF 导出与产物校验成功后才报告任务完成。
- 公开源仅完成匿名连接探测、原生 UTM COG 读取器和合成数据测试，未接入完整下载任务；界面明确禁用该路线的下载按钮。
- 官网源文件已经生成，但没有部署。真实 Google 登录、小规模真实 GEE 新下载及 macOS/Linux 实机认证仍需按验收矩阵完成；本轮没有发布或推送。
