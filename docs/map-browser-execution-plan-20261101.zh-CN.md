# AEF-GRiTS 地图浏览与下载联动执行方案

日期：2026-11-01。状态：**方案，尚未实施本轮业务代码变更**。

目标：借鉴 FTW Explorer 的地图交互与按需加载方式，让用户看清“哪里有格网、哪年有数据、本机下载了什么”，再进入已有下载流程。继续采用**本地运行、网页操作**；公开官网仍只负责介绍与安装指引。

本方案接续 [本地 GUI 执行计划](local-web-gui-execution-plan-20261030.zh-CN.md)，不重做已认可的首页、header、左侧步骤和下载管理布局，不替换下载引擎。

## 1. 先说明坐标系：3857 不是 UTM

| 对象 | 坐标系与单位 | 本项目中的用途 |
|---|---|---|
| 网页底图 | EPSG:3857，Web Mercator，单位米 | 地图显示、缩放与 XYZ 底图叠加；不是 UTM |
| 点位/AOI 交换 | EPSG:4326，WGS84，经纬度 | 输入点定位、GeoJSON、地图边界交换；不代表下载栅格也是 4326 |
| 官方 AEF 原始影像 | 各影像所在的本地 UTM，10 m | 原始 64 维年度特征；不是全球共用一个 EPSG |
| MGRS 下载栅格 | 对应格网的 UTM，10 m | CRS、原点、尺寸来自仓库内权威 MGRS 索引 |
| Tessera 0.1°选片下的 AEF 栅格 | 当前实现使用对应 UTM，10 m | 0.1°是选片单元，不是像元分辨率，也不是下载 Tessera 特征 |
| Reference 下载栅格 | 参考影像的投影与仿射变换 | 当前入口要求米制投影、10 m、北向上；不强制必须是 UTM |

WGS84 / UTM 北半球分区使用 EPSG:32601—32660，南半球使用 EPSG:32701—32760。例如 UTM Zone 50N 是 EPSG:32650，Zone 17S 是 EPSG:32717。[PROJ UTM](https://proj.org/en/stable/operations/projections/utm.html)、[PROJ Web Mercator](https://proj.org/en/stable/operations/projections/webmerc.html)、[Google AEF 产品说明](https://developers.google.com/earth-engine/datasets/catalog/GOOGLE_SATELLITE_EMBEDDING_V1_ANNUAL)

本轮本地只读核对：`50RMU → EPSG:32650`、`17MPU → EPSG:32717`、`17NQA → EPSG:32617`。这三个 MGRS 输出均为 10 m、10980 × 10980 像元。不能从地图底图的 CRS 推断这些输出的 CRS。

### 1.1 什么情况下会见到“4326 的 AEF”？

1. **点位表的坐标是 4326。** 输出为 `sample_id, lon, lat` 和特征列的 Parquet 属性表，并不是一幅 4326 栅格。经纬度用于定位，读取器可以把点转入 UTM 后查像元。
2. **GEE 拼接影像的默认投影可能是 4326。** 当前已有验收查询到了这种情况，是否如此须检查实际影像投影。合成或 mosaic 的默认投影不一定保留源影像 UTM；最终计算尺度还取决于采样/导出请求。默认 1°元数据不意味着请求 `scale=10` 后仍按 1°采样。[GEE 投影说明](https://developers.google.com/earth-engine/guides/projections)
3. **数据被明确导出或重投影到 4326。** 例如指定地理目标网格，或使用第三方已经重建的经纬度 mosaic。此时确实得到不同网格的栅格。应读取实际 CRS、transform 和产品来源，不能把所有匿名源统称为 4326。
4. **预览图或边界使用 4326。** 这只是展示/交换数据，不应据此更改原始 64 维产品。

当前 MGRS 与 0.1°路线显式向 `computePixels` 提供 UTM CRS 和仿射变换。Reference 路线拒绝 4326 参考栅格；它形式上允许合法的米制 EPSG:3857 参考，**但这不等于 UTM，也不保证地面实际 10 m**。

### 1.2 已发现的点位采样限制：必须先讲清，再验证

开发者本地保留的四点验收记录（`webapp/acceptance/storage_plan_20261030/points_audit.json`，未随仓库发布）显示：

- 原始影像为 EPSG:32649、10 m；当时查询到的 mosaic 默认投影为 EPSG:4326。
- 点位请求使用 `sampleRegions(scale=10)`，没有显式传入 `projection`。
- 因此不是 1°粗采样，但**不能宣称已经与原生 UTM 10 m 像元严格对齐**。
- 输出 `lon,lat` 保留输入点的位置，不是通过返回几何取得的采样像元中心。
- 四点的特征完整性检查通过，不等于原生像元对齐检查通过；该记录也不能推广为所有 mosaic 的投影。

`sampleRegions` 未指定投影时使用影像首波段投影，`scale` 决定名义尺度。只改界面为“UTM”不能解决采样网格问题。[sampleRegions 参数说明](https://developers.google.com/earth-engine/apidocs/ee-image-sampleregions)

严格对齐还要核对 **CRS + 仿射变换/原点 + 像元尺寸 + 行列位置**。两个产品都写“UTM、10 m”，仍可能错开半个像元。允许不插值的整数行列翻转或交换：相反数组行序不必然改变地面像元。与 S1/S2 融合需要目标参考网格一致，并不必然同时等于 AEF 原生网格。[GEE 精确网格导出说明](https://developers.google.com/earth-engine/guides/exporting_images)

后续真实核验已发现：五个历史小栅格窗口原生像元一致；四点现行采样取到邻近像元；UTM 边界 mosaic 存在跨区来源混入。详见 [2026-11-01 原生对齐报告](native-alignment-audit-20261101.zh-CN.md)。本计划仍未作为完整 GUI 改版实施。

## 3. 从 FTW 借鉴什么，不照搬什么

FTW 的重要经验是**把显示层与数据产品分开，并按视窗/缩放层级加载**，不是让浏览器一次读取全部全球遥感数据。

- 格网边界负责导航、选片；它不是影像本身。FTW 的全球下载格网与自定义推理的 Sentinel-2/MGRS 格网也不是同一种网格。
- 低缩放级别显示概览，高缩放级别再显示细节；不把全球细矢量一次塞给浏览器。
- COG/PMTiles 的分块或 Range 读取适合已有云端归档；不等于必须把 AEF-GRiTS 改造成同样的前后端栈。
- 年份、透明度、图层与地图位置适合保存在链接中；凭据、Project、磁盘路径和私人样本不适合。

首版继续 Leaflet + Flask + 现有 Python 依赖。只有性能测量证明 GeoJSON 或本地预览不能满足目标，再讨论矢量瓦片、COG 金字塔等后续工程。

参考实现：[MGRS 图层](https://github.com/fieldsoftheworld/ftw-inference-app/blob/main/src/layers/S2-Grid-Layer.ts)、[下载格网](https://github.com/fieldsoftheworld/ftw-inference-app/blob/main/src/layers/Download-Grid-Layer.ts)、[栅格概览](https://github.com/fieldsoftheworld/ftw-inference-app/blob/main/src/layers/Global-Overview-Layers.ts)、[细矢量 worker](https://github.com/fieldsoftheworld/ftw-inference-app/blob/main/src/workers/predictions-worker.ts)、[视图链接](https://github.com/fieldsoftheworld/ftw-inference-app/blob/main/src/composables/usePermalink.ts)。这些是研究依据，不是本项目已实现的能力。

## 4. 实施顺序与验收门槛

这里的 P0—P6 是工程阶段，**不是重新增加七个 GUI 操作步骤**。用户仍按现有数据源、空间、年份、保存下载主线操作。

### P0：坐标语义与点位采样正确性

**P0a，统一展示语义：**

- 地图说明显示“底图：Web Mercator”；点位说明显示“点坐标：WGS84 经纬度”。
- 格网详情显示“下载网格：UTM Zone 50N / EPSG:32650，10 m”；跨区任务列出各网格 CRS，不显示单一的全任务 UTM。
- 原生源投影、采样投影和目标输出投影分别记录；没有核验过的信息显示“未核验”，不从底图推断。
- 原有 10°经纬线只作为背景参考线，不标成 MGRS。

**P0b，点位原生网格采样独立修正：**

1. 为每个年份识别涉及的原始 AEF 资产及其投影/仿射网格；按实际源网格组织点，而不是给全国点统一指定第一个影像的 UTM。
2. 对原始影像或同网格组合显式使用完整源投影。重叠资产的选择顺序固定并记录；不能混用不同资产的部分波段拼成一个向量。
3. 继续保留输入 `sample_id,lon,lat`；来源记录保存资产 ID、年份、采样 CRS/transform 和采样像元位置，允许区分输入点与实际像元中心。
4. 多年份按年完成源网格采样后按 ID 组合，保证结果列和现有加载器兼容；没有有效数据时保持缺失，不补零。
5. 采样协议改变必须进入任务签名/来源元数据。旧检查点不能被误当成新协议成果；不自动重提取或覆盖历史 Parquet。
6. 使用同源、同网格的小栅格与点样本交叉核对，再检查跨 UTM 区、源影像重叠、像元边界和掩膜点。

**通过条件：** 对已确定源像元的有限值向量，点/栅格读取结果一致；边界选择可重复；旧结果能被识别而不被修改。若实际源量化/转换导致不能位级一致，须先解释误差来源并冻结可复现的数值容差，不以“都是 10 m”替代验证。

P0b 是采样协议修正，不是换投影标签。没有通过时，界面继续保留当前对齐限制；不宣称严格原生像元采样。

### P1：按当前视窗浏览真实格网

**用户体验：** 打开格网图层，放大到研究区，直接看到权威 MGRS 或 0.1°选片边界；悬停显示编号，点击加入选择。已选格网离开屏幕后仍保留。

**最小实现：**

- 新增只读视窗接口，例如 `GET /api/map/grids?scheme=...&bbox=...&zoom=...`。这是拟议接口，目前不存在。
- 请求 bbox 使用 WGS84 经度/纬度；返回 GeoJSON 边界与 `grid_id、目标 CRS、分辨率`。真实栅格仿射变换仍由现有 provider 决定。
- MGRS 索引在进程中按需加载一次，复用空间索引；不每次拖图读取整个 Parquet。
- 0.1°先估算候选数量，超过上限即要求放大，**不能先枚举全球数百万格网再裁剪**。
- 首版最多返回现有 `MAX_GRID_COUNT` 允许的数量，默认 500。过多时明确返回“请放大查看”，不静默丢掉剩余格网。
- 前端在 `moveend/zoomend` 后查询；初始防抖设为 300 ms，取消过期请求，并拒绝过期响应覆盖新视窗。参数为待标定初值，不是性能实测结果。
- 处理世界地图左右平移的经度归一化及跨日期变更线 bbox；不请求超出当前格网产品支持范围的极区。
- 同一 `grid_id` 的世界副本共享选中状态；地图拖动本身不修改 AOI 或已确认计划。

**选择语义：** 保留“上传/绘制 AOI 后选择相交格网”，增加“直接点击浏览格网”的入口。后者用已选格网建立任务范围，再经现有 provider 重算并进入预检，不能把当前屏幕 bbox 或客户端提交的几何直接当作下载任务。

切换网格体系时明确重置不兼容的选择，不能把 MGRS ID 带进 0.1°计划。浏览不需要 GEE Project，也不调用 Earth Engine；沿用本地应用既有访问控制。

**通过条件：** 全球视图不会加载全部细格网；缩放/平移不产生下载任务；选中内容保持稳定；单个 MGRS 下载范围与原有解析结果一致。0.1°地理索引边界和实际 UTM 输出矩形要分别命名，不能互相冒充。

### P2：年份与数据覆盖信息

格网存在不代表指定年份有有效 AEF，更不代表本地已下载。

首版采用逐层确认：

| 可展示信息 | 证据来源 | 不允许推断的结论 |
|---|---|---|
| 格网存在 | 本地权威索引/既有 provider | 不等于有 AEF |
| 该年源影像足迹相交 | 指定来源的年度资产索引/有限元数据查询 | 不等于每个像元有效 |
| 有效覆盖率已核验 | 对明确范围执行的掩膜检查 | 不推广到未检查区域或其他年份 |
| 覆盖率未知 | 尚无上述检查 | 不显示成 0% 或 100% |

- 地图平移只读取已有元数据与缓存，不逐格调用远端覆盖统计。
- 用户主动查询已选范围时，才做有限的来源/年份检查；覆盖率计算可复用 `scripts/check_aef_coverage.py` 中实际可复用的逻辑，保留其范围与资源限制。
- 记录核验时间、产品/来源、年份、AOI 分母及核验方式，避免把整个格网覆盖率当作 AOI 覆盖率。
- 当前 GUI 下载仍是 GEE 路线。公开源仅连通检查不能显示“可直接下载”；实验性 GCS 索引不能与 GEE 结果无标记混合。
- 年份以所选数据源实际可用性为准，不能单凭 GUI 年份按钮判断产品已经发布。

**通过条件：** 缺少授权时仍能浏览几何，但源覆盖提示未核验；零有效像元与未检查可区分；公开源不被误启用。

### P3：本地下载状态映射到格网

**用户体验：** 同一年份下，地图能区分未下载、排队、下载中、部分完成、已交付和失败；点击格网能打开对应任务记录与结果说明。

**实现范围：**

- 只读当前用户可访问的任务、catalog、验证结果和 GeoTIFF 交付清单。默认不递归扫描磁盘，不自动发现其他用户的数据。
- 不使用会逐个打开全部 Zarr 的读取器构建地图索引；先投影读取 Parquet 必要列，再按选中项读取详情。
- 明细至少以“产品/来源 + grid_scheme + grid_id + 年份 + 输出网格签名 + 交付记录”区分。相同格网的不同年份、数据根目录和来源不能被最后一条记录覆盖。
- 保留生产 catalog 的现有结构；地图在只读层展开年份，不为 UI 迁移整个数据目录或重写 catalog。
- 格网完成事件、任务完成/失败后更新缓存；沿用既有 SSE/轮询，不每个图层再启动一套轮询。
- `完成`、`产物结构验证通过`、`有效像元覆盖已核验`分开。已有验证若只证明文件结构，不能因此给格网涂上“100%有效”。
- GeoTIFF-only 结果由交付清单定位，不能因为临时 Zarr 已清理就判定数据丢失。

**通过条件：** 多年/多目录状态正确；重启后与任务记录一致；全 NaN 的结构合格产品不会伪装为有效覆盖；文件移动后详情诚实提示不可访问，不偷偷重下。

### P4：已下载 AEF 的轻量预览

目标是检查位置、缺失与年度空间纹理，**不是把 64 维嵌入解释成真彩色，也不是在线分类**。

**P4a，先完成小窗口预览：**

- 用户主动选择已交付格网、年份和地图窗口，才读取本地数据；首版限制单次源窗口不超过 512 × 512。
- 使用固定 A00/A01/A02 组合与固定数值映射生成 RGB，标注“AEF 特征伪彩色”。不同年份不各自自动拉伸，以免制造虚假的视觉变化。
- 用有限值/掩膜控制透明度；不把缺失值、零向量或透明背景当成低特征值。
- 沿用 Rasterio 处理 TIFF 和既有 Zarr 读取方式，只给浏览器返回小型预览，不返回全量 64 维数组。
- 预览可重投影到 EPSG:3857 与底图叠加；原始 UTM 产品与数值不变。必须按投影正确变换，不能把 UTM 图像仅贴上经纬度 bbox。
- 入口通过任务 ID、grid_id、年份和受限窗口定位数据；复用结果接口的权限检查，不提供任意本地路径读取接口。

**P4b，小窗口通过后再做整格网概览：**

- 按需生成最长边约 1024 像素的派生缩略图，分块读取、限制并发、写入独立预览缓存。
- 缓存键包含源交付/签名、年份、波段和渲染参数；改变年份不误用旧图。
- 当前 Zarr 的一个压缩 chunk 包含 64 个通道，即使只显示三个通道，解压成本也未必降到 3/64。没有金字塔的普通 TIFF 同样可能需要大量 I/O。
- 10980 × 10980 × 64 的 float32 数组约 28.7 GiB，禁止一次读入；256 × 256 × 64 原始浮点块约 16 MiB，内存预算还需计入解压、重投影与其他缓冲。
- 显示“正在生成预览”，复用已有资源限制和后台执行机制，不把全图处理放入同步网页请求；若不能小改动安全复用，首版止于 P4a，另行评审概览任务。
- 不修改原始 TIFF 的压缩/金字塔，也不自动对所有历史数据预计算。只有实际测试证明需要，再考虑独立预览 COG 与 overviews。

**通过条件：** 图像与已知控制位置对齐，偏差不超过一个预览像元；掩膜正确；原始 CRS/transform/科学数值不变；切换年份与快速移动不会显示上一请求的旧图。该容差仅用于显示，不替代 P0 的原生像元验证。

### P5：图层风格、详情与可分享视图

保留现有米色/绿色主界面，只完善地图内部层次：

- 默认只开底图与所需格网；本地状态、源覆盖、特征预览可单独切换，避免所有填色同时叠加。
- 未选格网用细灰线，悬停加强轮廓，选中用高对比描边。选中状态与数据覆盖状态分开表达。
- 下载完成用绿色，进行中用蓝色，部分/待核验用琥珀色，失败用红色；所有状态同时有文字，不只靠颜色。
- 只在足够缩放时显示格网编号；悬停先展示 ID、年份、简短状态，详情再显示 CRS、像元尺寸、覆盖证据、文件大小和任务链接。
- 科学文件大小与预览大小分别标注；没有实际统计时显示“未知”，不以估算冒充实存字节。
- 按钮“加入下载”仅更新选择并进入已有预检，仍需要 plan 确认；点击地图不是开始下载。
- URL hash 只保存地图中心/缩放、年份、格网类型、图层与透明度。不得放入 Project ID、token、磁盘路径、私人点位或 AOI 文件内容。
- 分享链接恢复的是视图，不恢复另一台电脑的本地文件、不自动登录或启动任务。

### P6：回归、说明与小规模验收

先完成不联网测试，再在用户授权下进行极小真实验证。不为地图验收下载完整 MGRS 或重复已有数据。

| 检查 | 用例与通过条件 |
|---|---|
| 坐标 | `50RMU/17MPU/17NQA`；确认北/南半球，地图 3857 与目标 UTM 不混淆 |
| 边界 | 跨 UTM 分区、跨赤道、跨日期变更线、世界副本、源影像重叠；ID/选择不重复 |
| 超限 | 全球 0.1°请求提前返回放大提示；不先创建巨量 GeoJSON |
| 交互 | 快速拖动、取消请求、隐藏图层、离屏选择、切换年份；不生成幽灵任务 |
| 可访问性 | 图层开关、格网详情和加入下载支持键盘操作与清晰焦点；状态不只靠颜色 |
| 来源 | 未授权 GEE、无该年资产、尚未验证公开源；状态诚实且不弹出自动登录 |
| 本地结果 | Zarr、Zarr+TIFF、TIFF-only、多年、多目录、缺失文件、全 NaN、部分覆盖 |
| 点位 | 单 UTM、跨区、边界、掩膜点；同源同网格的小栅格交叉核对 64 维值 |
| 预览 | 波段/年份正确、NoData 透明、投影正确、原始产品不变、内存不随全图大小增长 |
| 权限 | 不泄露其他用户任务；不能通过预览或分享链接读取任意路径/凭据 |
| 原功能 | 点位上传/绘制、格网上传/绘制/点击、预检确认、下载、断点、取消、结果查看 |
| 安装包 | 新增 Python/JS/CSS 资源确实包含在 wheel 中；从仓库外启动也能使用 |

性能验收记录实际数值，不提前写“全球秒开”：

- 几何响应 feature 数、响应字节、冷/热缓存耗时；局域本机热缓存查询初始目标为 1 s 内，不是已达到的结果。
- 连续平移后的网络请求数、过期响应丢弃情况、浏览器内存与掉帧情况。
- 预览首次生成时间、再次打开时间、Python 峰值 RSS 与磁盘读取量；观察是否影响已有下载吞吐。
- 浏览和读取已有结果期间，新增 EE 数据请求应为零；主动源查询/真实点位验证单独记录。

复用现有 pytest 与 Playwright。新增针对实际实现的测试，不复制业务逻辑作为“测试”。pytest 使用唯一的 `.test-tmp/<run-id>` 或工作区规定的临时目录，并设置 `--basetemp`、关闭默认缓存。真实验收报告和截图保存在 `webapp/acceptance/map_browser_<date>/`，不放进可随时清理的 pytest 目录。

## 7. 本轮证据与未验证项

本轮完成：静态检查格网、点位、GEE 请求、GeoTIFF、公开源、Web 入口；读取既有点位验收；本地解析样例格网及 CRS；核对 Google/PROJ 文档。

本轮未做：新 GEE 数据下载、公开源在线完整提取、浏览器性能验收、历史样本重提取、任何生产文件迁移。当前方案中的响应时间与预览大小为初始设计目标，不是实测性能保证。

关键风险：点位原生网格尚未严格锁定；结构验证不等于有效数据覆盖；大 MGRS 的首次预览可能受磁盘 I/O 限制。优先解决前两项，不能用更漂亮的地图掩盖数据语义问题。
