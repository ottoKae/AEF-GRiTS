# AEF 原生 UTM 像元对齐：真实小样本核验报告

日期：2026-11-01。性质：真实 Earth Engine 元数据与小块数值核验；不是全库验收，也不是下载器修复完成报告。

本文保留修复前的诊断口径；下文“当前/现行协议”指当时的旧协议。
已完成的修复见[实现与验收](native-alignment-implementation-20261101.zh-CN.md)。

## 1. 结论

**原生像元保存是合理目标；当前需要优先修复点位采样与跨 UTM 的源选择，不应据此要求所有历史栅格重新下载。**

| 检查对象 | 本轮结果 | 判断 |
|---|---|---|
| 已有五个格网/年份的小窗口 | 1,280 个像元、81,920 个特征值与同范围原生像元全部一致；掩膜无差异 | 所检查窗口通过，不能推广为完整瓦片通过 |
| 原生投影的点/栅格一致性 | 五个窗口的 45 个中心点，以及用户四点，共 49 个向量全部一致 | 显式原生投影可以取得一致结果 |
| 用户此前四点的现行采样逻辑 | 历史结果与当前逻辑 4/4 完全一致，但与包含输入位置的原生像元 0/4 一致 | 确认点位采样网格问题，不只是文案问题 |
| UTM 49/50 边界西侧目标窗口 | 256 个像元中，246 个匹配 50 区源映射到 49 区后的值，10 个匹配本区源 | 当前 mosaic 确实可能混入其他 UTM 源 |
| 边界东侧目标窗口 | 256/256 与 50 区本区源一致 | 本窗口通过；两侧结果不对称 |

最重要的术语修正：**数组行序不同，不等于地面像元错位。** 本轮 GEE 源资产的 y 方向为正，本地产品是常见 north-up 负 y；整数行列翻转可以完整保留像元，不需要空间插值。

## 2. 实际范围与资源

本机 Windows、`py312_torch` 环境，复用当前 Earth Engine 凭据。没有登录弹窗、切换账号、修改 Project 配置或启动远程服务器任务。

使用以下已有成果，全部只读：

- 17MPU：2017、2025 年；来自历史 256 × 256 的 Reference 测试产品。
- 17NQA：2017、2025 年；来自历史 256 × 256 的 Reference 测试产品。
- `grid_-79.95_-1.05`：2025 年；来自 0.1°选片的 256 × 256 probe。
- 用户 2026-10-30 下载的四个 2025 年点样本。

新增核验只请求 16 × 16 × 64 小块、少量点和元数据。另在中国 UTM 49/50 边界两侧分别检查小窗口，不下载整个 0.1°单元或 MGRS。

- 预设上限：60 次数据/元数据请求，单并发，每次 60 s deadline，最多一次可恢复重试。
- 实际：**54 次，全部成功，无失败重试**；凭据刷新和 EE 初始化不计入此计数。
- 保存 30 个小块 `.npy`，合计 **1,969,920 字节（约 1.88 MiB，含文件头）**。这是本地数组文件大小，不是实测网络流量。
- 54 次请求的计时累计约 56.30 s，不包括初始化、离线复核、测试及报告时间。
- 11 项相关本地测试通过；没有运行整个仓库测试套件。

## 3. 核验方法

### 3.1 固定源资产，区分三种对照

每个案例记录源资产 ID、年份、64 波段 CRS/仿射变换和版本属性；在源数量明确时进行数值比较。

1. **原生自洽检查：** 固定原始资产，用完整原生投影读取小栅格，再对预定像元中心调用显式 `projection` 的 `sampleRegions`，不附加 `scale`。
2. **历史格网检查：** 复现本地产品的目标网格，比较原始资产、当前年度 mosaic 和历史已存窗口。再读取完全相同地面范围的原生数组，通过整数索引翻转与历史窗口直接比较。
3. **历史点位检查：** 保留原四点整批 bbox 和年份，重建现行 `multiyear_image + sampleRegions(scale=10)`，与原 Parquet 及原生投影结果分别比较。追加 `geometries=True` 获取实际采样中心，定位它落入哪个原生像元。

比较同时报告：有效向量数、掩膜差异、逐元素相等数、完整 64 维向量相等数及最大绝对差。全零不自动作为 NoData；没有用余弦相似或丢弃缺失行代替精确比较。

### 3.2 正确的像元一致判据

同一 CRS 下，计算 `inverse(T_source) * T_target`，即目标像元坐标到源像元坐标的映射。

- 线性部分是带符号的置换矩阵，平移为整数：可以通过行列翻转/交换、整像元裁切得到相同地面像元，无须插值。
- 存在非整数平移、尺度变化或一般旋转：不能直接宣称原生像元一致。
- CRS 不同：即使重采样后的数值相同，也不能宣称保留了原生空间网格。

本轮第一阶段 `summary.json` 中的 `aligned` 检查相同数组方向，因此正/负 y 行序相反时返回 false。**最终像元判断应使用 `native_footprint_verification_v2.json` 的 `same_pixel_footprints`，不能把第一阶段 false 解读为实际错位。** 第一阶段原始记录保留，以便追踪判断过程。

## 4. 真实结果

### 4.1 五个历史栅格窗口：均与原生像元一致

| 区域/产品 | 年份 | CRS | 比较范围 | 64 维向量完全一致 | 最大绝对差 |
|---|---:|---|---|---:|---:|
| 17MPU Reference probe | 2017 | EPSG:32717 | 16 × 16 | 256/256 | 0 |
| 17MPU Reference probe | 2025 | EPSG:32717 | 16 × 16 | 256/256 | 0 |
| 17NQA Reference probe | 2017 | EPSG:32617 | 16 × 16 | 256/256 | 0 |
| 17NQA Reference probe | 2025 | EPSG:32617 | 16 × 16 | 256/256 | 0 |
| 0.1°选片 probe | 2025 | EPSG:32717 | 16 × 16 | 256/256 | 0 |

这些窗口的 64 个波段共享同一源网格；源与目标没有非整数像元偏移。对相应 MGRS provider 和 0.1°provider 的格网相位检查也一致。

GEE 原生资产使用 `yScale=+10`，本地使用 `yScale=-10`。原生数组经整数索引重排后与历史保存值全部相等，说明这里的方向变化没有改变像元范围或特征值。

**范围限制：** 前四个是位于相应 MGRS 内的小型 Reference 产品，不是对整个 MGRS 的数值验收；第五个也不是整幅 0.1°单元验收。只测试了 2017、2025，不能据此保证其余年份或其他源资产。

### 4.2 四个历史点：确认取到了邻近原生像元

| 对照 | 完整向量完全一致 | 掩膜差异 | 最大绝对差 |
|---|---:|---:|---:|
| 历史 Parquet vs 当前现行协议 | 4/4 | 0 | 0 |
| 当前现行协议 vs 显式原生协议 | 0/4 | 0 | 0.073079586 |
| 显式原生协议 vs 原生小栅格 | 4/4 | 0 | 0 |

当前现行协议与原生协议之间，256 个特征分量的平均绝对差为 **0.015071367**。这不是对分类精度损失的估计，仅是本轮四点的特征差异。

取回实际采样几何后得到：

| 点 ID | 现行采样落点相对原生正确像元的列/行偏移 | 输入点到现行采样中心的距离 |
|---|---|---:|
| map_1 | 列 0，行 -1 | 4.76 m |
| map_2 | 列 -1，行 0 | 4.74 m |
| map_3 | 列 +1，行 0 | 2.77 m |
| map_4 | 列 +1，行 +1 | 5.64 m |

行偏移以该 GEE 源资产的正 y 行序定义。输入点到采样中心距离与“原生像元中心间距”不是同一量：靠近边界的点移动几米就可能落入相邻像元。

每个历史向量都在其原生 16 × 16 邻域中找到唯一完全相同向量，且对应位置与取回的采样几何一致。当前候选源只有一个，所以本案例不能用多源优先级解释差异；历史结果又被现行协议完整复现。证据共同指向：**mosaic 的名义 10 m 采样网格与原生 UTM 像元不一致，导致取到了邻近像元。**

四个点不是随机总体样本，不能把“4/4”写成所有历史点 100% 错位。也不能把这些值称为损坏数据；它们是现行协议下可复现、但不符合用户原生取样要求的结果。

### 4.3 UTM 边界：目标 CRS 正确仍可能混入其他分区源

在同一边界区域检索到 EPSG:32649、EPSG:32650 两套源资产。

| 目标格网 | 当前 mosaic 与本区源一致 | 与邻区源映射到目标后的一致情况 | 判断 |
|---|---:|---|---|
| 49 区，16 × 16 | 10/256 | 50 区源有效 246 个像元，246/246 与 mosaic 一致 | 当前输出含其他分区源的映射结果 |
| 50 区，16 × 16 | 256/256 | 与 49 区源映射结果 0/256 完整向量一致 | 本窗口采用本区源 |

49 区目标窗口中，50 区源缺失的 10 个像元由其他源补足。这里并非文件标错 CRS，而是 **mosaic 先混合相交来源，再按目标网格求值**，没有限制只使用原生网格兼容的源。

该实验比较的是源在目标格网上的数值，用于辨别来源贡献，不把跨 CRS 后的数值一致当作原生对齐。后续严格模式应限制源网格或明确拆分，而不是仅设置输出 EPSG。

## 5. 修复优先级

### P0：先修点位，不改用户输入格式

- 输入仍接受 WGS84 `sample_id,lon,lat`。
- 按年定位原始源资产及网格，显式采样原生投影；记录源资产、采样行列与像元中心。
- 重叠源选择规则必须固定；不能按整批 mosaic 的默认投影采样。
- 改变采样协议后更新任务签名，新结果进入新批次。历史点表保留，不自动覆盖或混用旧检查点。

### P0：限制格网来源，避免跨 UTM 隐式重采样

- 请求前比较源与目标的 CRS、像元范围与整数偏移，允许无损行列翻转。
- 同网格源可以整像元拼接；不兼容源不能因目标写了 UTM 就当作原生数据。
- 若同区兼容源足够覆盖，则只使用兼容来源；覆盖不足时保留缺失并说明，或由用户明确选择跨区派生产品，不悄悄补入其他分区。
- 不要求放弃 MGRS/0.1°选区或现有 Zarr 布局；需要拆分时按源网格组织，并在 catalog 记录。

### P1：把本轮真实案例转成回归验收

- 原生点与原生小栅格必须一致，包含中心、边界两侧和缺失情况。
- 点位处理应不因输入分片大小或批次 bbox 变化而改变同一样本的原生来源选择。
- 格网验证需要覆盖正/负 y 行序、多个年份、跨区重叠与来源掩膜，不能只用常数合成数据。
- 已有历史栅格先按来源/网格审计，不做全量重下。
