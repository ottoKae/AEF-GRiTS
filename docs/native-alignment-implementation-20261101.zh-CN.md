# AEF 原生 UTM 像元对齐：实现与验收

验收日期：2026-11-01；发布拆分：2026-11-02。范围：下载协议修复、小数据真实验收与文档。
网页资源另在 `feature/web-workbench` 开发，不随本次下载内核更新合入 `main`。

## 结论

新下载采用 **`native-utm-v1`**：点位读取所在源像元，格网只接受像元边界一致的
原生来源。真实 GEE 小数据回归通过。此前四点样本的邻近像元偏移已在新输出中消除；
UTM 49/50 区重叠处不再混用不同投影源。**旧成果没有被修改，也不会自动升级。**

这项保证针对源像元身份及 float32 取值，不代表所有年份、所有区域已逐一实测，
也不是把源 double 数值逐位保存为 double。新任务会在下载前检查自己的实际源网格。

## 1. 修复的内容

### 点位

1. 输入仍为 WGS84 `lon,lat`；它是查询位置，不是输出栅格的 CRS。
2. 逐年查询真实相交的源资产，读取64个波段的 CRS、affine、尺寸和版本。
3. 将查询位置转换至源 UTM，确定所在像元的行列号及准确中心。
4. 使用明确的源投影采样，不再调用“多年度 mosaic + scale=10”的旧方式。
5. 当地 UTM 优先，同级按资产ID顺序选择首个完整64维向量，不拼接不同资产的波段。
   当地来源缺测时，其他重叠来源也只在其自身原生格网上取值，实际源CRS写入结果。
6. 一年缺测只让该年保持 NaN，不丢弃该样本其他年份的数据。

Parquet保留原特征名 `aefYYYY_center_A00`—`A63`，另存
`aefYYYY_source_asset/crs/column/row/center_x/center_y`；分片旁保存
`partNNNNN.native.json`。现有统一点位读取器仍可使用。

### 连续格网

源和目标必须同时满足：相同 UTM CRS、相同10米像元边界、整数像元位移。
相反的行方向可以无损重排行序，不要求 affine 的 y 符号相同。
不兼容的源明确排除；没有兼容源则报错，不创建栅格成果。兼容源内部缺测保留 NaN，
不借用其他 UTM 区的像元填补。报告逐年有效像元数量和比例。

MGRS、0.1°、reference 复用同一检查。0.1° 是选择和组织单位，实际输出仍为目标 UTM。
与 S1/S2/Tessera 融合时，还需要单独比较对方的分辨率、CRS、原点和像元边界；
不能因为同名瓦片或同为UTM，就声称逐像元一致。

### 来源与续传

- 协议、资产版本、来源选择和格网进入来源清单与签名。
- Zarr attrs、checkpoint、catalog、报告及 GeoTIFF tags/manifest 均保留来源。
- 点位与Zarr续传重新核对来源；旧协议或来源变化要求新输出目录，不能用
  `--overwrite` 或旧 ledger 绕过。
- 已完成 TIFF-only 允许凭冻结manifest离线核验／恢复，标记
  `completed_frozen_manifest`；它不声称再次查询过远端版本。
- 原有Linux NTFS隔离提交机制保留；最终Zarr核验通过原有隔离进程执行。
- 离线 `--plan-only` 仍离线，明确为 `unverified_offline_plan`。

### 其他入口

- 旧 Drive 格网导出接入同一源格网检查。
- 旧 Drive 点位导出不再提交任务，只保留 `--dry-run`；请改用正式
  `scripts.stream_aef_points_ee`。这样不会继续生成已知错位的旧协议数据。
- 实验性公共COG读取与新GUI留在网页分支，不属于本次GEE内核发布，也不构成正式第二数据源。
- 旧 `annual_image` / `multiyear_image` 保留用于历史诊断复现，文档明确其不保证原生对齐。

## 2. 真实小数据结果

所有任务使用现有用户凭据、单worker、小窗口；没有启动登录或整瓦片下载。

| 检查 | 实际结果 |
|---|---|
| 原来的4点，2017和2025 | 8个年度向量均完整 |
| 每片1点与每片4点 | 两年度结果完全相同 |
| 4点2025对照已捕获的原生源值 | 256/256个float32值完全一致；旧协议此前为0/4个完整向量一致 |
| 点位完成后续传 | 重新核验来源，通过 |
| 17MPU：2017、2025，各16×16 | Zarr及TIFF与原生参照逐值相同 |
| 17NQA：2017、2025，各16×16 | Zarr及TIFF与原生参照逐值相同 |
| 0.1°历史测试格网：2025，16×16 | Zarr及TIFF与原生参照逐值相同 |
| UTM49区边界：2025，16×16 | 只选EPSG:32649，排除32650，256个向量与本区原生源一致 |
| UTM50区边界：2025，16×16 | TIFF-only与本区原生源一致；完成后恢复通过 |
| 参考格网平移3米 | 正确拒绝，没有创建Zarr成果 |

合计 **7个栅格窗口、1,792个像元、114,688个特征值完全一致**；并非只比较均值或相关性。
两个点位批次和七个栅格批次，共 **9份交付通过现有产物验证**；点位统一加载器也通过。
TIFF-only只清理本次生成且已校验的临时缓存，没有删除历史数据。

## 5. 今后如何使用

现有点位／MGRS／0.1°下载命令不需要增加开关；新协议默认生效。为正式研究创建新批次
输出目录，先跑少量点或小reference窗口，检查 `native-utm-v1` 和来源清单，再扩大任务。

旧数据无需立即删除或全量重下。已有栅格可逐批核验；需要严格像元一致的旧点位样本，
应在新目录重新提取后再替换模型输入，不能只给旧文件加一个“已原生对齐”的标签。
