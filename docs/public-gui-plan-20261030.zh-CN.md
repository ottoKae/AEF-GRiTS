# AEF-GRiTS 公开网页下载平台设计与实施计划

> 主路线已调整：本文件中的公开服务器加工、凭据托管和浏览器文件交付不再作为当前实施方案。请以[本地运行、网页操作执行计划](local-web-gui-execution-plan-20261030.zh-CN.md)为准；本文件保留供方案对照，不与新计划并行实施。

日期：2026-10-30。状态：设计方案，尚未实施或部署。

## 1. 目标与 ponytail 边界

用户打开公开网址即可查看 AEF 覆盖、选择空间范围和年份、取得数据，无须安装本仓库或 Python。服务免费，明确展示软件作者与数据提供方。第一期只支持 AEF，不提前建设多卫星平台。

采用最小完整路线：**原始文件直达数据源；点位提取和对齐格网才由服务器加工。** 保留本地 GUI 和既有 GEE 下载器，在同一仓库的 `/portal` 上演进，不另建前后端项目。

本轮只更新本计划；不更改业务代码，不启动下载，不修改部署或推送 Git。

用户流程固定为：**P0 数据源与连接验证 → P1 选择位置 → P2 选择时间并查询 → P3 确认并下载到用户电脑。** P0—P3 以下均指这四个步骤，不再与上一版开发阶段混用。

不做：支付、积分、强制关注、微服务、Redis/Celery、Kubernetes、浏览器内完整 GIS 计算、全国数据预缓存，以及无实际需求的通用插件系统。公开服务必要的身份隔离、资源限制和数据完整性不能省略。

## 2. 当前实现与交付缺口

| 现状 | 公开版本处理 |
|---|---|
| `/` 本地 GUI，`/portal` 工作台，共用 Flask 和下载器 | 保留；公开配置不开放本地凭据模式 |
| 已有点位上传、地图选点、AOI 绘制及格网勾选 | 复用，不重写地图组件 |
| 已有预检、plan 确认、队列、任务状态、取消及恢复 | 复用，只补公开任务边界 |
| 当前任务依赖 GEE Project 和认证 | 原始公开文件查询不要求 Project；仅 GEE 路线要求 GEE 授权 |
| `/results` 返回验证信息、来源和服务器目录 | 还不是浏览器文件交付；须增加受控产物下载 |
| 用户可选择服务器输出子目录 | 公开端改为任务名称和结果下载，不暴露服务器目录 |

当前 `MAX_GRIDS=500`、`MAX_RAW_GIB=100` 等默认值面向既有工作流，不直接当作免费公开服务限额。现有未提交改动全部保留，不通过重建工作树实现本计划。

## 3. 数据源策略：优先原生 UTM，不把 mosaic 当作唯一入口

### 3.1 首选：官方公开 GCS COG

官方提供按年份和 UTM 分区组织的 COG 与空间索引，适合做覆盖查询和文件直链。文档当前列出 2017—2025 年，以及 provider-pays 设置；实际可选年份、可访问性及费用政策在上线时再次验证，不作为永久保证。[官方数据说明](https://developers.google.com/earth-engine/guides/aef_on_gcs_readme)

关键科学约束：64 个通道为有符号 int8 编码，`-128` 为 NoData。分析前先屏蔽 NoData，再按官方映射解码：`sign(q) * (q / 127.5)^2`。不得将存储整数直接当成模型特征，也不得宣称解码是对任意既有 float32 数据的无损恢复。科研采样读取基础分辨率，不能误取预览金字塔。[编码与解码规则](https://developers.google.com/earth-engine/guides/aef_on_gcs_readme)

### 3.2 备选：Source Cooperative 原生 UTM 版本

先验证 [Source Cooperative AEF](https://source.coop/tge-labs/aef) 的具体文件、索引、坐标方向、编码和访问条件，再决定是否启用。当前不能承诺它比 GCS 快或始终可访问；本次资料复查该网页返回访问错误。

若启用，用户明确选择来源，产物记录来源，不因网络错误静默混用两个提供方。针对该副本说明中的方向/VRT问题，必须用真实样本核查，不能仅根据 EPSG 判断正确。

### 3.3 既有 GEE 与 EPSG:4326 mosaic

- GEE 与免数据源登录路线在 P0 并列可选；保留本地 GEE 能力，完善公开网页授权与 Project 绑定，不要求免登录源用户先登录 GEE。
- GEE 小影像可生成直接下载链接，但 `getDownloadURL` 有 32 MB 和格网维度限制，不能替代大型 MGRS Zarr 加工。[接口说明](https://developers.google.com/earth-engine/apidocs/ee-image-getdownloadurl)
- [Source Cooperative mosaic](https://source.coop/tge-labs/aef-mosaic) 不列为首期科学提取默认源。EPSG:4326 再转 UTM 会涉及采样；影响是否可接受须实验确认，不以“坐标系改变”直接断言精度损失大小。

## 4. 两条交付流程

| 路线 | 用户取得什么 | 数据流 | 登录要求 |
|---|---|---|---|
| 原始文件 | 与 AOI 相交的原始 COG、链接清单及来源说明 | 数据源 → 用户浏览器 | 默认无需登录，不需要 GEE Project |
| 定制提取 | 点位 Parquet，或对齐目标格网的 Zarr | 数据源 → 受限加工服务 → 用户浏览器 | 加工前网站登录；仅使用 GEE 时另行授权 |

原始 COG 的覆盖范围不等于 MGRS 或 Tessera 0.1°格网。**相交查询不等于裁剪**：用户可能下载到 AOI 以外的像元。界面必须同时显示源文件范围与用户 AOI。

定制模式才提供：点位、MGRS、Tessera 0.1°三种输出；0.1°只是索引单元，实际 AEF 栅格仍按选定 UTM 10 m 格网组织。Reference 继续保留本地能力，公开首期不增加该入口。

直接链接可绕开本服务器大文件中转，但不能解决用户无法访问数据源的问题。普通链接下载与 JavaScript 跨域 `fetch/Range` 是两种能力，必须分别验证；不能因前者成功便假定 CORS 已通过。

## 5. 四步页面与操作设计

### 5.1 布局

```text
顶部：AEF-GRiTS | 嵌入式特征数据下载工具 | 使用说明 | 作者/源码 | 登录
┌─────────────────┬─────────────────────────────────────┐
│ P0 数据源验证  │ 地图：AOI、点位、源文件/目标格网覆盖 │
│ P1 选择位置    │ 点击显示年份、CRS、实际范围、可用性  │
│ P2 时间与查询  │ 图例明确区分源覆盖与目标格网         │
│ P3 确认与下载  ├─────────────────────────────────────┤
│ 条件完成度     │ 查询结果 | 我的加工任务              │
│ 当前缺失条件   │ 最新任务靠左，横向滚动，详情可展开   │
└─────────────────┴─────────────────────────────────────┘
```

沿用现有字号、按钮和地图，不照搬参考网站的复杂导航。所有必要功能可键盘操作，状态不能仅靠颜色表达。手机端地图和表单上下排列。

### 5.2 P0：数据源选择、登录与连接验证

页面提供两个入口：

| 入口 | 用户操作 | 就绪条件 |
|---|---|---|
| 公开数据源（无需 GEE 登录，推荐） | 选择已验证可用的官方 GCS；备选源通过验证才显示 | 索引可查询、代表性对象可访问；浏览器直下能力另行标明 |
| Google Earth Engine（需要授权） | Google 授权 → 输入自己的 Cloud Project ID → 验证连接 | 当前用户凭据与所选 Project 联合验证成功 |

“无需登录”明确指访问该公开数据源与查询/原文件直下。若用户要求本站提供耗资源的定制提取，P3 仍需网站身份和配额，但不要求其有 GEE 账号或 Project。界面提前注明，不能先承诺全程匿名再临时强迫 GEE 登录。

#### 公开网站的 GEE 绑定

1. 用户点击“连接 Google Earth Engine”，跳转 Google 官方授权页面，可选择账号；不在本站输入 Google 密码。
2. 复用现有 OAuth 回调，校验 state 和身份，服务端安全保存凭据；页面仅显示当前账号和授权状态，不暴露 token。
3. 用户输入自己的 **Cloud Project ID**，不是显示名称、邮箱、OAuth Client ID 或密码。初版手动填写并记住该用户已验证的选择，不为项目自动枚举新增一整套权限。
4. 服务端使用该用户凭据和该 Project 做小规模真实 EE 请求，确认可调用 API 和目标 AEF 集合；分别报告未授权、项目未启用/未注册、权限不足、配额或网络失败。仅“Google 登录成功”不算验证通过。
5. 绑定“网站用户 + Google 身份 + 凭据版本 + Project”，复用现有绑定机制。确认的查询/plan 使用该绑定；切换账号、Project 或来源后，旧查询与未提交 plan 失效，需要重新验证，不静默更换运行任务身份。
6. 提供“重新验证”“切换账号”“断开连接”。断开移除本站保存的相关授权并停止接纳该绑定的新任务，明确提示运行任务会中断或需要重新授权；Google 全局撤销授权与单纯退出本站不是同一动作。

项目须满足 Earth Engine 注册、API 启用及当前用户权限要求；授权与项目初始化是两个步骤。[Earth Engine 认证说明](https://developers.google.com/earth-engine/guides/auth)

运营者配置 Web OAuth client、同意页、域名和精确 HTTPS 回调地址；客户端密钥只保存在服务器配置中，不让普通用户提供。使用现有 OAuth 库，按实际 scopes 完成 Google 要求的发布/验证，不自行实现 OAuth。[Web OAuth 流程](https://developers.google.com/identity/protocols/oauth2/web-server)

#### 本地 GUI 与公开网页的区别

| 场景 | 凭据从哪里来 | 不能做什么 |
|---|---|---|
| 用户访问公开网站 | 本次网站 OAuth 授权 | 网站不能自动读取访问者电脑上的 ADC/EE 凭据文件，也不能把网站服务器 ADC 当作该访问者身份 |
| 用户自己运行 localhost GUI | 原有协议发现当前 OS 用户的 EE/ADC 凭据；网页输入 Project 后验证 | 不因浏览器中已登录 Google 就假定本地 Python 已授权 |
| 本地尚无凭据 | 明确“尚未认证”，用户主动执行已有认证流程后点击重新检测 | 下载过程中不能自动运行登录或无限重试授权 |

用户已经在 Google 或 GEE Code Editor 登录，可能简化账号选择，但不等于已授权本站。公开网站授权也不会自动替用户执行 `earthengine authenticate` 或写入其本机凭据目录。

本地页面提供已有认证文档入口和适用命令提示，不再建设第二套登录守护进程。公开网页只用 HTTPS 正式回调；localhost 特例不能用于公开 IP 部署。[回调规则](https://developers.google.com/identity/protocols/oauth2/web-server#redirect-uri-validation)

### 5.3 P1：选择位置——点位或格网

| 目标 | 上传文件 | basemap 交互 | 输出含义 |
|---|---|---|---|
| 点位 | CSV（sample_id、lon、lat，WGS84）或 Point Shapefile（含完整组件和 CRS） | 点击添加/删除多个点，自动生成稳定 sample_id | 所选点对应的年度64维特征，不默认下载整幅 COG |
| 格网 | Polygon Shapefile 等已支持矢量文件作为 AOI | 绘制范围，预览并勾选相交格网 | 选择 MGRS 或 Tessera 0.1°目标格网 |

沿用现有上传入口支持的其他格式，不新增解析库。CSV 非经纬度坐标不靠数值猜 CRS，提示先转换或提供带 CRS 的矢量。Shapefile 缺 `.prj` 不静默认定 WGS84；Polygon 不能冒充点位输入自动取中心。

地图统一用经纬度展示，数据输出使用相应 UTM 格网；显示输入 CRS、定位点/范围和最终目标格网，避免屏幕坐标与输出坐标混淆。上传/绘制是明确二选一的当前输入来源，切换后显示真正生效的范围。

原始文件下载作为格网流程中的交付选项：可用所选格网检索相交源 COG，但必须注明“未裁剪、不是所选 MGRS/0.1° Zarr”，不得悄悄替换用户要求的产品。

### 5.4 P2：选择年份，公开查询

1. 按当前来源的实际库存选择年份，可多选；AEF 是年度产品，不显示虚假的月/日下载选项。
2. 点击“查询数据”。仅进行覆盖查询和必要预检，不启动全量数据下载或后台批量提取。
3. 地图高亮有覆盖、无覆盖或部分覆盖的对象；表格显示年份、点数/格网ID、来源、目标 CRS、交付格式、估算量与数据流路线。
4. 区分“源文件覆盖该区域”与“每个点/像元有效”：未读取像元时标注“有效性待提取验证”，不能将相交覆盖率作为完整率。
5. 查询通过后生成可确认的 plan；没有覆盖或超出公开限额时说明原因，不显示可执行下载。

公开源查询无需 GEE 权限；GEE 查询使用 P0 绑定。改动来源、身份/Project、位置、年份或交付格式均使原 plan 失效，界面提示重新查询。无数据和请求失败分别展示。

### 5.5 P3：确定下载，保存到用户本地文件夹

最终确认卡只保留：来源、范围、年份、文件格式/估算量、是否先加工，以及“保存到我的电脑”。不要求用户填写服务器输出目录。

**“下载到本地”指用户访问网页这台电脑，不是部署网站的服务器。** 网站不能凭用户输入 `D:/downloads` 或 `/Users/...` 就写入该路径。

两种保存方式共用同一下载结果，不额外建设本地客户端：

- 支持目录访问 API 的浏览器：用户主动点击“选择本地文件夹”，授权后将响应流写入文件，不把整个大型文件先读成内存 Blob。仅在源跨域读取也可用时用于外部直下；同源加工结果也可使用。
- 不支持或用户不授权：使用浏览器普通下载，由用户的“下载前询问保存位置”设置/另存为对话框决定目录。界面说明“保存位置由浏览器管理”，不假装已选目录。

`showDirectoryPicker()` 需要安全上下文和用户操作，兼容性有限，不能保证所有 Safari/Firefox/移动浏览器均可用；按功能检测决定入口。[浏览器目录接口](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)

用户取消目录选择不启动新加工任务。现有同名文件不无提示覆盖；简单提示换名或由用户确认即可，不实现复杂同步器。目录权限失效时允许用户重新选择；首版不承诺刷新页面后自动续写本地文件。

| 下载产品 | 确认后的实际过程 | 本机保存 |
|---|---|---|
| 源 COG | 浏览器直接访问数据源，无需本站重打包 | 原始文件；多文件逐项保存/授权后串行保存，另附清单 |
| 点位特征 | 服务器按点提取或采用已验证的 GEE 小结果直链；不改变已确认格式 | 分片 Parquet 及说明的 ZIP；若未来提供 GEE CSV 直链须作为明确的另一格式 |
| MGRS/0.1° Zarr | 有界队列中完成提取、对齐、验证和打包，再开始网络传输 | ZIP_STORED 包；用户解压即为标准 Zarr 与 catalog |

因此，“直接下载到本地”作为所有流程的交付目标可以实现，**但不能承诺任意点位/Zarr 都完全绕过服务器计算，也不能保证确认后立即开始传输尚未生成的数据。** 不让用户安装 Python，不依赖 Google Drive 手动中转。

普通外部链接即使能下载，也未必允许脚本跨域流式写入所选文件夹；此时保留普通下载，而不是未经同意把数十GB文件改经本站代理。大文件由浏览器下载管理器/支持的 Range 处理，网页不宣称已具备跨会话断点写入。

### 5.6 四步进度与任务信息

- 顶部显示 P0—P3 四个真实步骤：源已验证、空间已确定、时间查询已通过、下载已确认。每步25%的进度明确称为“配置流程”，不是数据下载进度。
- 每一步可展开查看缺失条件；完成 P3 后另开任务进度，不用“配置100%”冒充“下载完成”。
- 预检显示当前阶段：输入解析 → 覆盖查询 → 数据量/资源检查 → 等待确认；未有可测分母时用进行中状态，不编造百分比。
- 加工进度采用已完成/总块或分片数，排队不显示假 ETA；验证和打包单独显示。
- 外部直链只显示“链接已打开/交由浏览器下载”，服务端没有完成证据时不显示“100%完成”。
- 任务卡包含目标、范围、年份、来源、CRS、状态、产物大小与过期时间；路径改为下载按钮，错误显示可操作原因。
- 同时提供紧凑卡片和详情展开，避免长路径、验证状态挤掉正文。

## 6. 对齐与数据产品约定

点位输入统一转换为 WGS84 供定位，再变换到源栅格 CRS 查找像元；这是坐标转换，不需要先重投影整幅影像。输出保留请求坐标、实际像元中心、源文件及像元索引；落在同一像元的不同样本不能静默合并。

对齐格网不能只检查“同为 UTM、10 m”：还要冻结 EPSG、仿射变换/原点、尺寸、像元中心、掩膜及边界裁剪。MGRS 使用仓库自带权威格网，不依赖另一仓库路径。跨 UTM 区按既有目标格网规则处理，不能把多分区强行标成同一 CRS。

新增 COG 读取与既有写出衔接，优先复用 rasterio、点位/格网组织、catalog 和验证器。目标格网需要重采样时首版采用最近邻以避免混合 embedding，同时记录方法和位移；这仍不是“严格无损”，上线前要与源像元及 GEE 样本对照。

| 产品 | 输出约定 |
|---|---|
| 原始 COG | 保留源文件与编码，不重新压缩或改写；附使用说明 |
| 点位 | 复用分片 Parquet 与 catalog；明确 sample_id、year、64维特征、有效性及来源 |
| 格网 | 复用年度维度 Zarr、年份坐标和 catalog；float32、Zstd-7、no-shuffle，chunks=(1,64,64,64)、shards=(1,64,512,512) |
| 加工交付 | 一个 ZIP 包，已压缩数据使用 ZIP_STORED；附相对路径 catalog、README、provenance 和 SHA-256 |

先验证现有 Zarr 维度顺序再写入上述尺寸，不另建第二套存储实现。打包需把临时包空间计入资源预留；校验完成后发布，失败不把半成品当作结果。

## 7. 服务器、资源和公开访问边界

### 7.1 最小部署

一个现有 Python 应用、一个调度进程、现有任务子进程，前接 HTTPS 反向代理。生产 WSGI 服务采用单进程线程模式；具体服务软件由目标服务器环境决定，不使用 Flask 开发服务器承接公开流量。

鉴权后由反向代理提供加工产物的断点下载，应用负责权限检查；不让一个 Flask 请求长时间搬运大型文件。输出目录不得配置为匿名目录浏览。

### 7.2 建议试运行限额，须实测后冻结

| 项目 | 初始建议 |
|---|---|
| 原始文件覆盖查询 | 限查询频率与单页结果数；无需预读全部影像 |
| 单用户加工 | 1 个运行任务、1 个等待任务 |
| 全站加工 | 初始 1 个运行任务；总等待上限 10，测量后再考虑 2 并发 |
| 点位 | 初始每任务最多 10,000 点、1 年 |
| 格网 | 初始只试开放单个 0.1°格网、1 年；完整 MGRS 加工通过内测后再开放 |
| 存储 | 按源读取、输出、打包和安全余量预留；不足则拒绝确认 |
| 结果保留 | 建议完成后 72 小时，页面明确告知；不清理运行任务 |

这些不是性能结论。公网开放前还须根据可承担的带宽/磁盘预算，冻结每用户每日加工字节上限和全站预算；不能只限制任务数量。限额只约束本站计算与托管流量，不能承诺控制外部源文件的传输。

### 7.3 必须覆盖的真实风险

- 公网匿名用户可反复提交加工任务耗尽资源：加工要求网站身份，服务端执行限额；不把校验只放前端。
- 当前本地模式代表同一操作系统用户：不能作为共享网站身份，公开配置误用时拒绝启动。
- 上传文件和结果路径是信任边界：复用入口校验，检查压缩展开大小、路径越界和几何类型；内部不层层重复验证。
- 任务编号可被猜测：任务、日志、结果和下载均校验所有者；不输出命令中的凭据、真实服务器目录或他人信息。
- 不接受用户任意远程 URL 作为影像源，只允许受支持索引生成的对象地址，避免把服务变成代理。
- 私有上传与结果按用户隔离；共享缓存仅限公开源对象。退出登录不删除他人或运行中的任务。
- 保留现有崩溃恢复、磁盘及文件系统检查。Linux 控制状态与高频写入使用健康 ext4/XFS，不宣称 Python 能避免内核文件系统死锁。

这些是公开部署的必要边界，优先复用已有代码；不由此扩展为复杂安全平台。若实现中发现需明显增加新框架或流程，先单独说明并确认。

## 8. 流量、成本与科研复现

10,000点 × 64维 × float32，单年仅特征值约2.56 MB；100 km见方、10 m像元的64维float32约25.6 GB，尚未计掩膜、压缩及实际格网范围。二者不能使用同一资源策略。

COG 的压缩传输体积按实际对象大小统计；定制结果解码后的大小不能当作源下载量。点位结果很小也可能触发大量分散 COG 块读取，应分别测量请求数、源读取字节、CPU、峰值内存、结果字节及服务器出站字节。

成本示例而非预测：若每天托管交付100个500 MB产物，一个月约1.5 TB出站流量。原始文件直链可减少这部分本站流量，但加工、缓存、打包和结果下载仍有成本。

每个加工任务保存来源/版本、索引版本、源对象标识、年份、输入摘要、目标 CRS/transform、解码及采样方法、软件 commit、完成验证和校验和。外部来源变化不可仅靠可变 URL 追溯；有对象校验和/版本信息时一并保存。

网页保留作者、联系方式、源码与引用方式；数据提供方署名与软件作者署名分开。按数据许可标注 Google/Google DeepMind，不暗示本站是官方服务。[数据许可](https://developers.google.com/earth-engine/guides/aef_on_gcs_readme)

隐私说明列清上传数据、登录信息、保留时间和删除方式。免费不等于无限服务，也不自动获得第三方 API 或底图的额外使用权限。

## 9. 按 P0—P3 实施与验收

开发顺序与四步界面一致；各步完成不等于可独立公开，最小完整闭环通过后才对外开放。

| 步骤 | 实施范围 | 必须通过的验证 |
|---|---|---|
| P0 数据源验证 | 公开源检查；网站身份与 GEE 授权分离；Project 联合验证；本地凭据重新检测 | 免登录源不触发 EE；GEE 正确账号/Project 成功，错误或取消授权有明确错误；换账号后旧 plan 不再可提交；不读取公开服务器本地凭据冒充用户 |
| P1 选择位置 | 复用 CSV/Shapefile 解析、地图选点、AOI绘制及目标格网选择 | WGS84点CSV、投影点Shapefile、Polygon AOI、地图输入定位一致；错误几何/缺CRS被解释；来源切换后只使用当前输入 |
| P2 时间与查询 | 实际年度库存、覆盖表、体积估算、plan 与限额 | 缺年份/部分覆盖/无覆盖正确显示；查询不启动批量下载；修改范围或年份后旧确认失效；源覆盖不冒充像元有效率 |
| P3 下载到本机 | 本机目录能力检测、普通下载回退；COG读取接现有提取器；验证、打包、权限和产物交付 | 真正落盘到访问者电脑；产物可读、坐标与年份正确；大文件不整包进入浏览器内存；他人产物不可访问；取消、低磁盘、重启恢复及过期清理正确 |

### 9.1 P0 的科学与网络证据

少量跨年份/UTM文件验证匿名访问、Range 206和浏览器 CORS；记录用户侧和服务器侧网络差异。对照 GEE 的方向、掩膜、波段顺序、解码值、余弦差异及边界，测量后设定容差，不预设两源位级相同。

每个来源只能在自身验证通过后启用。若目标用户无法访问 GCS，验证原生备选；不能把“服务器可下载”描述成“用户浏览器可直下”。授权失败不得静默改用管理员 Project 或另一数据源。

### 9.2 首次端到端验收矩阵

| 案例 | 从 P0 到 P3 的验收目标 |
|---|---|
| 公开源 + 地图点选 + 单年 | 无 GEE 登录；小规模点位加工完成并下载有效Parquet包；需要网站身份时提前说明 |
| GEE + 投影坐标点Shapefile + 单年 | OAuth与Project绑定正确；与对应点位提取结果核对；本机取得结果 |
| 公开源 + AOI绘制 + 原始文件 | 文件直接来自源端，源足迹与目标AOI清晰区分，网站不虚报完成 |
| GEE + AOI上传 + 单个0.1°格网 | 查询、确认、生成Zarr、验证、打包、本机保存全部闭环 |
| 公开源 + 单个MGRS格网（内部测试） | 与既有reader兼容；UTM对齐、资源预留、断点恢复和打包空间正确；通过后才决定是否公开 |
| 浏览器差异 | 支持目录API的浏览器验证授权与流式写入；不支持的浏览器验证普通下载；取消和重名文件不误覆盖 |
| 账号与任务隔离 | 两个测试用户互不可见产物；Project切换不污染另一任务；退出和断开行为与说明一致 |

先完成小点位闭环，再验收0.1°及MGRS，避免第一次就启动大任务。文件保存结束后检查校验和和内容，不仅检查网页显示“成功”。

### 9.3 公开发布门槛

HTTPS、OAuth发布要求、底图许可、权限/限额、隐私和错误脱敏须在开放前通过。保持单调度进程，先小范围邀请用户，记录延迟P50/P95、成功率、峰值内存/磁盘和网络字节再调整并发。

测试复用现有 API、认证和浏览器套件，不复制业务逻辑。fixture 放入 `tests/`，证据放入 `webapp/acceptance/`，临时数据遵守 `.tmp/tests/` 规则。同步中英文说明，分别说明公开网页登录/本机保存与本地GUI认证/服务器路径，不能混写。

## 11. 上线前需要确认的运营选择

建议默认采用“公开源无需 GEE 登录 + 可选 GEE 授权”，两者共用 P0—P3 流程；原始文件直下匿名，加工使用网站身份及限额。先贯通小点位/小格网，再决定大型 MGRS 开放量。以下信息影响部署而不阻塞本计划：

1. 公开域名、服务器位置、可承受月流量及数据盘预算。
2. 主要用户网络区域；是否普遍可达 GCS 或 Source Cooperative。
3. 公开作者姓名、联系方式及引用信息。
4. 是否接受建议的72小时结果保留期，以及加工试运行限额。
5. 首批支持的浏览器；推荐先认证桌面 Chrome/Edge 的目录保存，同时保证其他浏览器普通下载可用，实际以功能检测为准。

**推荐下一步：先实施 P0 的双源连接与 GEE 绑定验证，再按 P1→P2→P3 完成同一条用户流程。本轮仅改计划，尚未执行这些实现和验收。**
